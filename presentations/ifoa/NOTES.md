## Template mechanics

- `ifoa_life_template.pptx` — the IFoA template as supplied (untouched copy). Never edit it.
- `ifoa_life_reference.pptx` — generated by **`build_reference.py`** from the template; used as
  Quarto's `reference-doc`. Re-run the script if the IFoA template is updated. It does three things:
  1. **Renames six layouts** to the fixed names pandoc looks for (XML only, design unchanged):

     | IFoA layout | Renamed to (pandoc name) | Used for |
     |---|---|---|
     | Single column | Title and Content | ordinary bullet/table slides |
     | 1_Two Columns | Two Content | `:::: {.columns}` slides |
     | Two columns - in 3rds | Comparison | two columns with headings |
     | Single column + image | Content with Caption | text + one image |
     | Blank with footer - Colour | Section Header | `#` level-1 headings |
     | Blank with footer - White | Blank | image-only slides |
  2. **Adds missing placeholders**: the Title Slide layout's `title` becomes `ctrTitle` (40pt) with a
     new `subTitle` beneath (subtitle, presenters, date land there); a `title` placeholder is
     injected into the section-divider layout. Without these, title and section slides are blank.
  3. **Consolidates three slide masters into one.** This was the cause of the PowerPoint
     "repair" prompt: pandoc carries only `slideMaster1` but copied relationships pointing at
     `slideMaster2/3`, `customXml`, `authors.xml`, `handoutMaster`, `changesInfo` — none present in
     the output. The script keeps the content master, re-points all 19 layouts at it, and drops
     the dangling parts. Diagnosed 28 Aug by diffing PowerPoint's repaired save against the
     original (`hwle_ifoa_life_2026_repaired.pptx`, kept locally, not in git).
- **`fix_pptx.py` post-render step** (run automatically via `_quarto.yml`): pandoc writes body
  placeholders with no position, relying on layout inheritance that PowerPoint does not resolve
  for the IFoA layouts' custom placeholder indices — text landed at the slide origin, unwrapped,
  over the title. The script copies each placeholder's geometry from its layout into the slide,
  sets wrap + shrink-to-fit, renumbers duplicate shape ids that pandoc emits on picture and
  table slides, and corrects the package relationship type for `docProps/app.xml` (pandoc 3.1.2,
  bundled with Quarto 1.9, writes `package/.../metadata/extended-properties` instead of
  `officeDocument/.../extended-properties` — a repair trigger on its own, present even with no
  reference doc).
- **Repair-prompt history (28 Aug)**: three independent triggers were found by diffing PowerPoint's
  repaired save against the render, in two rounds: (1) dangling relationships from the
  three-master template → fixed in `build_reference.py`; (2) the wrong `app.xml` relationship type
  from pandoc → fixed in `fix_pptx.py`; (3) a bug in an early `fix_pptx.py` that left shapes with
  two `<p:spPr>` elements (pandoc writes `<p:spPr />` with a space) → fixed. Verification after the
  fixes: 0 dangling rels, 0 duplicate ids, 0 shapes with ≠1 `spPr`, correct package rels.
  **Status: PowerPoint still prompts to repair on first open, but the repaired file is complete
  and correct. Decision (Jon, 28 Aug): not cost-effective to chase further — the hand-off
  workflow is open → accept repair → Save As, and circulate the repaired copy.** If it ever
  matters (e.g. IFoA submission portal rejects the file), repeat the diff-the-repaired-save
  method; the remaining cause has not been identified.
- **Verification without PowerPoint** (no LibreOffice on this laptop): unzip the pptx and check
  (a) every `.rels` target exists, (b) no duplicate `<p:cNvPr id>` per slide, (c) one master,
  (d) expected `<a:t>` text on title/section/content slides. Both scripts' checks were clean on
  28 Aug; still eyeball the deck in PowerPoint after each render.
- **Pandoc slide splitting**: when a slide mixes a table or image with bullets, pandoc may push the
  overflow onto an untitled continuation slide (e.g. the HWP Tool slide). Keep one block type per
  slide, or accept the split and title it by hand.
- Other IFoA layouts (3/4 columns, thumbnail gallery, background image) are not reachable
  from Quarto; apply them by hand in PowerPoint after the final render if wanted.
- **Format choice**: pptx is less native to pandoc than reveal.js, but it is what the IFoA
  requires and it lets co-presenters edit without touching the codebase. Once content is
  finalised, the last-mile polish will be done in PowerPoint, not re-rendered.

## Main vs. Supplement

The .qmd is split into a **MAIN DECK** and a **SUPPLEMENT**. The supplement is grouped under the
main section each slide would fold back into (Why this matters / Survey approaches / CMI rates /
Close), so at each iteration we can review it and decide per slide: promote, keep as appendix, or
delete. Anything in main that turns out to be detail goes down to the supplement. Question slides
are deleted before submission; the supplement is either deleted or kept as a labelled appendix.
